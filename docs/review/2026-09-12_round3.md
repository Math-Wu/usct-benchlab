## External runtime evidence and Round-4 boundary

Inspected the existing `openbreastus_diffusion/kwave_dps/run_full_pipeline.py`
and `matlab/MultiFrequencyWaveformInvOpenBreastKWave.m`, plus
`Functions/HelmholtzSolver.m`, without modifying any external project.
The pipeline defaults simulation coefficients to 0.0025 and 0.06, so removing
flags without replacement would re-enable absorption. Fixed command values
therefore override even earlier expert argument occurrences. Its joint frequency
list is empty and material iteration schedule is zero. `a0` is positive PML
strength, not tissue absorption initialization; its description is corrected.

The legacy MATLAB runtime can inherit fixed material state from datasets or
warm starts. This PR does not certify arbitrary old artifacts as zero-absorption
runs. Sound-speed MAT import ignores unknown material arrays. Round 4 must handle
runtime/artifact validation and any exact compatibility changes needed for
`lucian-dw/WaveformInversionUST`. No `wfi.request.v1`, fork modification or
consumer repository changes are part of this work.

- Full local suite: 687 passed, 3 skipped (existing CUDA/MATLAB opt-in skips).
- Separate before/after runs of CGLS, SIRT, SART, native Eikonal, Full-Green Born
  and Tiny FWI produce identical SHA-256 hashes of reconstructed arrays. Compared
  the PR-2 head's source (merged unchanged) against this tree, same Python/runtime,
  8x8 deterministic cases and two iterations/steps. This is a numerical regression,
  not an imaging-quality calibration.

  `5.7766e-4` to `5.7640e-6` (order 2), on unchanged active stencils.
