# Recoverable baseline acceptance

The numerical campaign and algorithm changes are documented in
[the 64-channel results report](2026-09-08_64_channel_results.md).
This additional checkpoint adds an executable acceptance gate; it does not
introduce a new imaging algorithm or change reconstruction defaults.

A rebuilt CPU workspace recovered the exact source tree of commit
`2de5aea8f556bdecd071dfb7f624b77fcdd135b7` from its GitHub Actions archive:
`b498a46277c32bfd21f1a9b0892b49c132518524`. It reran package verification
(61 files and 12 HDF5 array/schema checks), the 199-test suite (199 passed,
2 external MATLAB tests skipped), and all four complete original baselines.
The original source tree was kept separate and unchanged during these runs.

`check_64_baselines.py` now compares saved arrays, tissue/water/residual scores,
evaluation mask policy, receiver split, status, actual termination reason,
selected/completed iterations, and simultaneous stop triggers. It records file
hashes and explicit failed checks. Missing, corrupt, failed or nonfinite output
cannot pass. Runtime equality is deliberately not required across CPU hosts.
Default absolute tolerances are 1e-9 m/s for arrays and 1e-9 for numeric metrics;
this is floating-point reproducibility, not a clinical quality threshold.

The gate was executed on the newly rerun four baselines and passed. The campaign
shell driver invokes it after the high-band pixel baselines and before the
basis experiment. Ten new tests cover mismatched arrays, nonfinite values,
changed policy/split/selection, failed/missing results and metric changes.
The expanded full suite passes 209 tests with the same two MATLAB skips.
The shell wrapper is syntax-checked; its constituent commands are executed
individually, not represented as an additional end-to-end wrapper run.

```bash
python scripts/check_64_baselines.py \
  --reference /path/usct_handoff_64/baselines_64 \
  --actual /path/reproduced_64 \
  --out /path/fresh_baseline_acceptance.json
```

Input acquisition files are never modified or uploaded to GitHub. Recovery
replays produce fresh logs and reconstructed arrays, not borrowed timing from
the first CPU run. Their time curves reflect their actual concurrent CPU load.
